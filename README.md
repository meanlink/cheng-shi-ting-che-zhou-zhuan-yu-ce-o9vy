# 城市停车周转预测

`parking-turnover-forecast` 面向“云栖城市交通运营中心”的停车调度小组。项目把每日闸机进出汇总、停车场容量变更确认、季节性周转预测和现场提醒串成可追溯流程。

## 启动

```bash
docker compose up -d --build --wait
open http://localhost:18246
```

停止并清理演示数据可执行 `docker compose down -v --remove-orphans`。

## 业务工作流

1. 分析师核对 `停车闸机_2026-11.csv` 的每日进出记录和 `环城东路枢纽停车场` 当前 420 个车位。
2. 运营人员确认 A/B/C 区当前占用，补录 `2026-11-21` 的高峰出场数据。
3. 分析师建立 `PF-20261123-07`，选择 7 天预测窗口。
4. 后端按星期季节性移动平均生成预测，并用滚动回测计算 MAE/MAPE。
5. 若日历存在缺口，或停车场容量变更没有现场确认，发布按钮和接口都会阻止发布。
6. 运营主管复核误差和容量快照后发布。
7. 运营人员按高峰日创建“南入口分流”提醒并发送到现场调度屏。
8. 主管确认提醒执行，审计事件记录操作者和时间。

## 技术与目录

- `frontend` 使用原生 HTML、CSS 和 ES modules，由 Nginx 提供静态页面。
- `backend` 使用 FastAPI、PostgreSQL 和 JWT，领域代码按 workflow、contracts、auth、middlewares、analytics 分层职责组织。
- `worker` 持续写入心跳，并从 Redis 取出预测运行事件做异步记录。
- `db` 为 PostgreSQL 16，`redis` 用于队列和限流计数。

共享枚举在后端 `src/contracts.py`、数据库迁移 CHECK 约束和前端 `src/constants.js` / `src/view.js` 同步出现。角色枚举用于 `src/auth.py`、`src/app.py` 和各页面权限分支。预测状态枚举贯穿 `src/contracts.py`、`src/workflow.py`、迁移约束和前端状态标签。提醒状态枚举贯穿 `src/workflow.py`、迁移约束和 `src/pages/alerts.js`。

## 停车运营扩展

| 工作台 | 现场运营 | 分析师 | 运营主管 |
|---|---|---|---|
| 临时封控 | 提报施工窗口，撤销待审工单 | 查阅 | 批准，或取消未绑定有效分流的封控 |
| 跨场分流 | 关联封控和已发布预测，登记接收场站，核算并启用预留；撤销草稿或未到运营日的分流 | 查阅 | 查阅 |
| 分流复盘 | 查阅 | 填写结班台账及实绩，补正退回单 | 退回补正或通过并结案 |

现场为 `PARK-07` 提出 75 位施工封控，主管核对 420 位的场站容量和日期冲突后批准，临时可用容量为 345 位。现场调度选择同场、同日的已发布预测，向 `PARK-12` 预留 26 位。启用时以接收场容量减去日期内已批准的封控、当前占用及当天已承诺的车位，结果不足时拒绝。预留是同日的保守容量承诺。结案后仍计入该日承诺，次日自动落出计算范围。系统记录内部调度安排，现场通过工单与接收岗交接。

### 预测逐日换版与版本锁定

同一场站可以有两份已发布预测覆盖同一个运营日。跨场分流只允许引用该运营日“在用”的预测版本，避免选到已被换掉的旧周转预测值。

- 运营主管在预测工作台按 UTC 运营日逐日换版：`POST /forecasts/versions/switch`，未被分流占用的日期可在覆盖该日的已发布预测之间切换，已人工换版与默认版本在 `/forecasts/version-days` 中均可查到。
- 已启用（`active`）或已结案（`closed`）的跨场分流所在运营日自动锁定，沿用分流当时引用的原版预测与数字；分流撤销且当天再无启用/结案分流时才解锁。结案日转为 `diversion_closed` 永久冻结。
- 换版与分流启用并发时由行锁串行化：先启用即锁住当天，后来的换版被拒绝；先换版则引用旧版本的分流草稿不能启用，需按当天在用版本重新安排。
- 换版请求带唯一 `request_id`，落库到 `forecast_version_switch`（含 `processing` 并发占位）。回执丢失后同号重试只重放首次结果，绝不重复换版；处理中崩溃会回收占位，被拒绝的请求同样占用 request_id。
- 旧分流和复盘保留当时写入的 `forecast_turnover` 等快照数字，不受后续换版影响；老库升级时 `004_forecast_versions.sql` 自动把已有启用/结案分流回填为锁定版本。


各运营日按 UTC 划分，与原有周转日序列一致。来源场站结班后，分析师填写台账编号与实际分流车辆。系统统计该日到当前时刻为止的闸机进出次数并留存快照，计算实际周转减去预测周转的差值。预测为零时偏差率显示为空。主管退回后分析师重提会产生新版；通过后复盘和分流状态在同一事务内更新。

扩展 API 位于 `/operations/closures`、`/operations/diversions`、`/operations/settlements`。角色常量继续使用 `src/contracts.py` 和前端 `src/constants.js`，新增流程状态在 `002_operations.sql`、`src/operations.py` 和前端 `src/pages/operations.js` 对齐。老数据库启动时自动补建三张表，重复 seed 保留已有的业务状态。

## 高峰溢流与交班

现场用「溢流调度」将已发布的来源场站预测关联到另一运营停车场，安排同一 UTC 运营日内的 15 分钟至 8 小时接收窗口。演示数据提供 `PF-OVERFLOW-YYYYMMDD` 和次日的 `OF-AM-YYYYMMDD` 待批准窗口，环城东路枢纽可向江畔文体中心移交 24 个备用车位。演示预测以预置历史观测为样本。值班人员在实际运营时应选择经预测工作台发布的方案。

| 工作台 | 现场运营 | 分析师 | 运营主管 |
|---|---|---|---|
| 溢流调度 | 提报窗口、在安排时间内开放入口、清场后结束 | 查阅 | 批准、撤销未开放窗口、暂停或恢复收车 |
| 溢流闸机 | 登记闸机批次 | 查阅 | 查阅 |
| 交班盘点 | 查阅 | 对照独立台账提交或补正 | 退回平账版本或通过并结案 |

1. 确认来源预测、接收场、开场时间和车位配额。主管批准时，从接收场容量扣除当前占用、已批准封控和同日跨场分流承诺。接收场同一时段只允许一张有效溢流单，旧分流流程也会核减溢流配额。
2. 当班门岗开放入口，系统以最新场站占用重新核算配额。记录带唯一单号的进出批次。混合批次先核销出场，再判断是否还有车位。以相同单号和数量重试只返回原记录。
3. 通道临时受阻时主管可暂停收车。暂停期间和计划时间到期后，门岗仍可登记离场。尾车清场后，现场运营结束窗口并释放预留车位。
4. 分析师对照交班台账提交进、出累计。任一计数与闸机流水不符时保存差异版本，需补正后才能提交主管审阅。通过后对应窗口同步结案，差异版和退回版仍可查阅。

新接口使用 `/overflow/windows` 及其 `decision`、`gate`、`closeout` 子路径。新增状态枚举在 `backend/src/overflow_rules.py`、`backend/migrations/003_overflow.sql` 和 `frontend/src/overflow/labels.js` 对齐。实际收车记录依赖值班人员录入，接收场占用来自现有的观测流程。
